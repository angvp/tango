# Jobs use fixed skip-on-overlap concurrency, no built-in retry, and silent skipped-tick diagnostics

A `Job` whose previous `Run` is still active when its next tick fires has that tick **discarded permanently** — never queued, never converted into "run again immediately after the current one finishes." This is the only concurrency policy, fixed framework-wide, not a per-`Job` option. We considered both alternatives — let concurrent invocations overlap, or queue/serialize the next one — and rejected both: overlap has no bound (a `Job` that reliably runs longer than its `Interval` accumulates unboundedly many concurrent invocations), and serialize/queue just delays the same problem into unboundedly growing latency instead of unboundedly growing concurrency. Skip is the only one of the three that can't silently pile up unbounded work. A discarded tick produces no signal at all — no log line, no counter, nothing — deliberately: a synthetic "overrun" diagnostic invented now, with no real consumer asking for one, risks guessing wrong about the shape (a counter? last-skip timestamp? `-tango-status` field?) a future observability need would actually want. This mirrors the project's own standing principle against building for hypothetical future consumers, already applied to `-tango-status` gaining no lifecycle field.

There is no built-in retry for a failed `Run` (returned error or recovered panic, treated identically): the framework calls `Run` once per tick, reports the failure, and waits for the next regularly-scheduled tick. We considered a fixed bounded retry with backoff, configured via new `Job` fields, and rejected it for the same reason `ratelimit` shipped no storage interface (see ADR 0029): a retry policy has several genuinely different reasonable shapes (fixed count, exponential backoff, jittered, circuit-breaking) and no real consumer has asked for any specific one yet. A host that wants retries wraps its own `Run` in retry logic — an ordinary Go function wrapping another is already sufficient, no framework primitive required.
