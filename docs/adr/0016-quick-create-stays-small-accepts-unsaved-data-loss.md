# Quick-create accepts unsaved-parent-form data loss and ships a narrow, internal preselect convention rather than a general feature

Admin's quick-create adds a `+` link next to an admin FK select, taking the user to the related model's create page and back — Django-admin-inspired, but deliberately without Django's popup. Two consequences of that "no popup" choice were real trade-offs, not obvious defaults, so both are recorded together here.

**Unsaved data loss is accepted, not engineered around.** A full-page navigation away from an in-progress create/edit form loses every field the user hadn't saved yet — clicking `+` next to `Book.AuthorID` while mid-way through typing `Title`/`Year`/`Price` loses all of it. Considered and rejected: round-tripping the parent form's other field values through the `next` URL (real engineering scope — works for simple inputs, gets awkward for anything using the wider `Widget` machinery or free-text content in a URL) and restricting the `+` link to edit forms only, where an object already exists in the database (removes the link from exactly the workflow — creating a `Book` and discovering its `Author` doesn't exist yet — that motivated the feature). Accepted instead: document the trade-off plainly, and let the feature be what it is — a few saved clicks for the common case, not a data-loss-proof workflow.

**The preselect mechanism (returning from related-object creation with the new object already selected) is internal plumbing, not a general admin feature.** It's a query-string convention the `+` link and its own return trip agree on privately, not a documented, stable `admin.Options`-level "initial values for any field" capability. Considered and rejected: generalizing it now, since a future feature (e.g. a "duplicate this row" link) could plausibly want the same mechanism — rejected because quick-create's own goal is staying smaller than Django's related-object tooling, and no concrete second use case exists yet to justify the larger, documented surface.

Both decisions optimize for the same thing: shipping the workflow the bookstore dogfooding app actually needed, without quietly growing it into general-purpose admin infrastructure nobody asked for.
