# Admin ships by default in `tango newproject`, opt out via `--no-admin`

Admin registration was originally a deliberate explicit step apps opt into (see the tutorial and [admin registration](../guides/admin-registration.md)), consistent with never running more than what a user asked for. This decision reverses that for the `tango newproject` scaffold specifically: the generated project includes `admin.New(...)` by default, with a `--no-admin` flag to skip it. We picked default-on because a scaffolded project that can't show off admin without a manual wiring step undersells the framework's actual ergonomics goal — a new user's first `go run .` should demonstrate the whole stack, not require a follow-up edit. This trades a larger default attack surface (every scaffolded project now serves `/admin/` unless told not to) for that first-run experience; the trade is kept safe because the scaffold ships no admin account at all: `/admin/` has no login until someone runs `tango admin create <username>`, so there is never a default or hardcoded password to guess. (An earlier version generated a random password into a file outside source control; session login with CLI-created accounts replaced it.) A reasonable reader coming from admin's documented "explicit opt-in" framing should not assume that framing changed everywhere — it changed only for the scaffold's default output, not for `admin.New`'s own API, which still requires an explicit call.
