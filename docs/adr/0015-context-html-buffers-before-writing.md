# `Context.HTML` buffers a template render before writing, and admin's own renderer is unified onto it

`func (c *Context) HTML(status int, tmpl *template.Template, name string, data any) error` is the root package's first public rendering helper for server-rendered (non-JSON) apps, added after the bookstore dogfooding app found it missing. `admin/render.go` already had a private helper with the same shape, used internally since the admin theme landed: it calls `ResponseWriter().WriteHeader(status)` and then streams `tmpl.ExecuteTemplate` directly to the response.

`Context.HTML` does not copy that streaming approach. It renders into an in-memory buffer first, and only calls `WriteHeader`/writes the body if `ExecuteTemplate` fully succeeds; a template execution error is returned unwritten, so it becomes an ordinary view error — a clean framework-generated 500, exactly like any other view failing today — rather than a response that already committed a status code (frequently `200`) followed by a truncated or malformed HTML body the client has no way to distinguish from a real page.

The streaming approach avoids one buffer copy per rendered page and is admin's shipped behavior today, effectively unnoticed because admin's own templates rarely fail mid-render. But a public API used by arbitrary apps' arbitrary templates doesn't get to assume that, and "the status code lied and the body is broken" is a strictly worse failure mode than "a 500 came back" for something as cheap as one extra copy of a page-sized buffer. `admin/render.go`'s private helper was rewritten to call the new public `Context.HTML` rather than keep its own separate, less-safe implementation beside it — leaving both in place would have meant the framework's own admin was measurably less safe than the API it hands apps.

Considered and rejected: keeping the streaming behavior for parity with admin's existing (silent) precedent — rejected because "that's what we already had" isn't a reason to carry a worse failure mode into a new stable public contract when fixing it costs one buffer copy.
