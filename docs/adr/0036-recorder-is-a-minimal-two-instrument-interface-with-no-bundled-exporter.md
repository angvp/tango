# `observability.Recorder` is a minimal two-instrument interface, low-cardinality attributes only, no bundled exporter

tanGO's metrics contract is a two-method interface — `AddCounter(name string, delta int64, attrs ...slog.Attr)` and `ObserveHistogram(name string, value float64, attrs ...slog.Attr)` — with no `Gauge` and no generic single-method catch-all. `NopRecorder{}`, a genuinely stateless empty struct, is the default everywhere a `Recorder` isn't explicitly configured. The `observability` package ships only the interface, `NopRecorder`, and the framework's stable exported metric-name constants — no Prometheus or OpenTelemetry adapter, interface-only.

We considered a single generic `Observe(event string, value float64, attrs ...)` call instead: it would have pushed the semantic distinction between "this is a rate" and "this is a distribution" onto string-naming conventions the host has to invent and remember, rather than the type system. We considered a fuller, Prometheus-`Registerer`-shaped surface (explicit metric registration, `Gauge`, label-set pre-declaration): it would drag cardinality/registration machinery into a contract meant to stay backend-agnostic, and no first-party instrumentation point needs a `Gauge`. We considered shipping a bundled exporter subpackage (e.g. `tango/metrics/prometheus`) alongside the interface: deferred until a concrete consumer asks for one, matching the framework's general discipline of not building speculative options ahead of demonstrated need.

Every attribute passed to `Recorder` methods must be a low-cardinality, bounded dimension — never a raw URL, error message, `UserID`, `RoomID`, or other unbounded/host-supplied value. This is enforced by centralizing each framework-internal metric emission behind a small typed helper and asserting exact attribute keys and values in behavioral tests with a capturing `Recorder`, not by a static source scan (a scan can't prove a value assigned to an *allowed* key, like `route`, is itself bounded). Getting this wrong silently turns a metrics backend into an unbounded time-series generator — a failure mode expensive to notice and expensive to reverse once real dashboards depend on the resulting label set, which is why it's a hard rule rather than a style guideline.
