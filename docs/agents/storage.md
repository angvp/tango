# Agent Recipe: File Uploads and Storage

Use this when an app accepts a user-uploaded file, keeps it, or serves it back.

Canonical files: `storage/storage.go`, `storage/upload.go`, `storage/serve.go`, `storage/local/local.go` and `storagetest/suite.go`. Runnable proof: `examples/uploads` (a document locker with `storage/local`, and `storagetest.NewMemory()` in its test). Human guide: `docs/guides/uploads.md`.

## Rule

- Depend on `storage.Store` (`Put`, `Stat`, `Open`, `Delete`); construct the concrete store in `main`: `local.New(dir)` for development and one host, `s3.New(ctx, s3.Config{…})` (module `github.com/angvp/tango/storage/s3`) for several instances or an ephemeral disk.
- Read an upload with `storage.Upload(store, r, storage.UploadOptions{PutOptions: …})`. `MaxSize` is required; put the type policy in `PutOptions.AllowedTypes` (sniffed, such as `image/*`), never in code that trusts `DeclaredType`.
- Keep the returned `Key`, `Size`, `SHA256` and `ContentType` in an app-owned model; use `tango:"varchar=n"` on its strings. There is no `FileField`, no file model and no listing.
- Write order: `Upload`, then the row in `store.InTx`, then `Delete` the new object if the row fails. To remove: delete the row first, the bytes best-effort, with `context.WithoutCancel`.
- Authorize in the View, then deliver with `storage.Serve(w, r, store, key, storage.ServeOptions{Filename, InlineTypes})`. Return a missing or foreign document as `404`.
- Upload routes carry their own larger `tango.MaxBodySize`; routes with no file keep a small one. A route limit can be lowered, never raised.
- Tests: `storagetest.NewMemory()`; `storagetest.Run` for a custom `Store`.

Tiny shape:

```go
file, err := storage.Upload(objects, ctx.Request(), storage.UploadOptions{
	PutOptions: storage.PutOptions{MaxSize: 4 << 20, AllowedTypes: []string{"image/*"}},
})
```

## Don't

- Do not build a key, path or object name from a client filename; keys are generated by `Put`.
- Do not use a key, `Filename` or `DeclaredType` as an authorization or validation input.
- Do not add a public URL, a static file route over the upload directory, or signed URLs; every download goes through a View and `Serve`.
- Do not call `Put` without a positive `MaxSize`, or skip `AllowedTypes` for user content.
- Do not expect `Upload`, `Serve` or a `Store` to log; the host's View logs the outcome it knows.
