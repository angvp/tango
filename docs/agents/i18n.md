# Agent Recipe: Localization

Use this when an app or reusable package needs translated server-rendered text.

Canonical guide: `docs/guides/i18n.md`. The admin already uses this API and renders English fallbacks until the host enables locale middleware and catalogs.

## Build

- Keep English fallback text inline and use stable, namespaced symbolic keys.
- Register plain Go-map catalogs explicitly; reusable apps do this in `App.Register`.
- Install `i18n.Middleware(nil)` in `Config.Middleware` to resolve `Accept-Language`, or supply a host-defined `LocaleResolver`.
- Call `i18n.T(ctx.Context(), key, fallback, args...)` from a View or other request-scoped code.

```go
i18n.RegisterCatalog("es", map[string]string{
    "books.list.title": "Libros",
})

title := i18n.T(ctx.Context(), "books.list.title", "Books")
```

## Rules

- Catalogs merge per locale; a later registration replaces only colliding keys.
- A missing locale, catalog, or key returns the English fallback.
- For dynamic copy use matching `fmt.Sprintf` placeholders in fallback and catalog text.
- `es-MX` falls back to an `es` catalog when no `es-MX` entry exists.

## Don't

- Do not introduce gettext, JSON/YAML catalogs, extraction tooling, plural rules, or automatic locale persistence for this API.
- Do not use English prose as the key; use names such as `books.list.title`.
- Do not assume installing admin automatically enables locale resolution.
- Admin widget script messages use `{count}`/`{max}`/`{error}` placeholders, not format verbs; keep them in translations (key list: the guide's "What the admin translates").

- A worked host setup (catalogs, `Chain`, a language switcher, completeness test): `examples/api-with-admin`.

## Check

- Exercise a translated request and the missing-translation fallback.
- Test any custom resolver separately from rendering.
- Run `docs/agents/checklist.md`.
- Locale tags match without regard to case or `-` versus `_`; the catalog's first-registered spelling is the resolved locale.
- A catalog value must use the same format verbs as the fallback (reordering with `%[2]s` is fine); an empty or mismatched value is ignored and the fallback is shown. Write a literal percent as `%%`.
- To find untranslated keys while running in a locale, set `i18n.OnMissing(func(locale, key string))`; it fires once per (locale, key) for absent, empty or mismatched values. Clear it with `i18n.OnMissing(nil)`.
- `i18n.Keys()` and `i18n.Validate()` read the keys that have run with a resolved locale (not a startup check): exercise your pages in the locale in a test, then assert `Validate().Problems` is empty. `Unobserved` catalog keys are advisory. Fallbacks must be literals (4,096-key cap).
- In tests, call `i18ntest.Isolate(t)` before registering catalogs; it restores the previous state in `t.Cleanup`, and the test must not be parallel.
- To let users pick a language: `i18n.MiddlewareResolver(i18n.Chain(i18n.FromQuery("lang"), i18n.FromCookie("lang")))`, then `Accept-Language`. Helpers return only registered locales and never set cookies; set the cookie in your own view. Use `i18n.FuncResolver(f, "Cookie")` for a custom source.
- With the i18n middleware installed, responses get `Vary` (from the resolver; `Accept-Language` for the default) and `Content-Language` (only when a catalog was selected). A plain function resolver adds no `Vary`: wrap it with `FuncResolver(f, "Cookie")`.
