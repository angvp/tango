# Agent Recipe: Localization

Use this when an app or reusable package needs translated server-rendered text.

Canonical guide: `docs/guides/i18n.md`. The admin already uses this API and renders English fallbacks until the host enables locale middleware and catalogs.

## Build

- Keep English fallback text inline and use stable, namespaced symbolic keys.
- Register plain Go-map catalogs explicitly; reusable apps do this in `App.Register`.
- Install `i18n.Middleware(nil)` in `Config.Middleware` to resolve `Accept-Language`, or supply a host-defined `LocaleResolver`.
- Call `i18n.T(ctx.Context(), key, fallback, args...)` from a View or other request-scoped code.

```go
i18n.RegisterCatalog("es", map[string]string{
    "books.list.title": "Libros",
})

title := i18n.T(ctx.Context(), "books.list.title", "Books")
```

## Rules

- Catalogs merge per locale; a later registration replaces only colliding keys.
- A missing locale, catalog, or key returns the English fallback.
- For dynamic copy use matching `fmt.Sprintf` placeholders in fallback and catalog text.
- `es-MX` falls back to an `es` catalog when no `es-MX` entry exists.

## Don't

- Do not introduce gettext, JSON/YAML catalogs, extraction tooling, plural rules, or automatic locale persistence for this API.
- Do not use English prose as the key; use names such as `books.list.title`.
- Do not assume installing admin automatically enables locale resolution.

## Check

- Exercise a translated request and the missing-translation fallback.
- Test any custom resolver separately from rendering.
- Run `docs/agents/checklist.md`.
